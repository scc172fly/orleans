# 将 Orleans 7.x 升级至 10.x

<a id="starting-and-target-assumptions"></a>

## 起始与目标版本假设

本指南假设：

- 应用程序首先更新至最新 Orleans 7.2 补丁版本。
- 应用程序能够在采用 Orleans 8 之前，将目标框架从 .NET 7 调整为 .NET 8。
- 每个主版本检查点均可独立部署和验证。
- 应用程序已使用 Orleans 7 的软件包、托管、标识及序列化模型。

受支持的检查点顺序为：

1. 在应用程序当前运行时上使用最新 Orleans 7.2。
1. 在 .NET 8 上使用最新 Orleans 8.2。
1. 在 .NET 8 上使用最新 Orleans 9.2。
1. 在所选软件包支持的 .NET 版本上使用当前 Orleans 10.x。Orleans 10.4 及以前的软件包面向 .NET 8 和 .NET 10；后续软件包面向 .NET 10 和 .NET 11。

不要在一次生产部署中合并 .NET 目标框架调整、Orleans 软件包更新、提供程序迁移及应用程序契约变更。

<a id="prepare-the-orleans-7-application"></a>

## 准备 Orleans 7 应用程序

迁移到 Orleans 8 之前：

- 将所有 `Microsoft.Orleans.*` 软件包统一到同一最新 7.2 补丁版本。
- 移除过时 API 并解决分析器警告。
- 确认 Silo 使用 `Microsoft.Orleans.Server`，客户端使用 `Microsoft.Orleans.Client`，共享契约项目使用 `Microsoft.Orleans.Sdk`。
- 确认托管使用 .NET 通用宿主及 <xref:Microsoft.Extensions.Hosting.OrleansSiloGenericHostExtensions.UseOrleans*> 或 <xref:Microsoft.Extensions.Hosting.OrleansClientGenericHostExtensions.UseOrleansClient*>。
- 盘点序列化成员 ID、别名、提供程序名称、流分区数及数据库架构。
- 保存有代表性的持久化状态及经过测试的恢复点。

调用筛选器应已使用 Orleans 构建器上的 <xref:Orleans.Hosting.GrainCallFilterSiloBuilderExtensions.AddIncomingGrainCallFilter*> 或 <xref:Orleans.Hosting.GrainCallFilterSiloBuilderExtensions.AddOutgoingGrainCallFilter*> 注册。旧的 <xref:Orleans.Hosting.GrainCallFilterServiceCollectionExtensions.AddGrainCallFilter*> API 自 Orleans 7 之前便不受支持，并非 Orleans 10 的变更。

<a id="move-to-orleans-92"></a>

## 迁移到 Orleans 9.2

完成[将 Orleans 8.x 升级至 10.x](8-to-10.md) 中所述的 Orleans 9.2 检查点：

- 决定是接受新的默认策略 <xref:Orleans.Runtime.ResourceOptimizedPlacement>，还是注册 <xref:Orleans.Runtime.RandomPlacement>。
- 移除自适应 Grain 目录缓存配置。
- 测试已统一的 <xref:Orleans.IGrainState`1> 读取和清除语义。
- 仅在运行时检查点稳定之后才采用原生 <xref:System.Threading.CancellationToken> Grain 方法参数。

<a id="move-to-orleans-10"></a>

## 迁移到 Orleans 10

完成[将 Orleans 9.x 升级至 10.x](9-to-10.md)。Orleans 10 特有的变更主要集中于：

- 过时的 <xref:Orleans.Concurrency.UnorderedAttribute> 和 <xref:Orleans.OrleansConstructorAttribute> 特性标注。
- <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 的默认值更改为 `false`。
- SQL Server ADO.NET 提供程序迁移至 `Microsoft.Data.SqlClient`。
- 取消支持扩展至观察者和系统目标。

通用宿主模型、基于构建器的调用筛选器注册，以及版本容错序列化模型保持不变。

<a id="serialization-state-and-providers"></a>

## 序列化、状态及提供程序

Orleans 7 引入了后续版本使用的标识与序列化器模型，因此从 7 升级到 10 不需要执行 Orleans 3 所需的标识转换。

仍需保留应用程序契约：

- 切勿重新编号或重复使用 <xref:Orleans.IdAttribute> 值。
- 在类型或程序集移动时保持 <xref:Orleans.AliasAttribute> 值稳定。
- 不要重新排列 record 主构造函数参数。
- 在每次运行时升级期间保持存储序列化器及提供程序名称稳定。
- 在每个检查点测试提醒器、流订阅、排队的有效载荷及具有代表性的 Grain 状态。
- 按顺序应用 ADO.NET 迁移脚本，验证每个提供程序后再继续升级。

<a id="deployment-and-rollback"></a>

## 部署与回滚

文档中的混合版本保证覆盖同一主版本系列内的补丁版本和次版本差异，而不覆盖 Orleans 7、8、9 和 10 同时部署在一个集群中的情形。对于每次主版本过渡，除非确切的版本组合已通过自己的混合版本测试套件，否则均使用并行集群。

保留先前集群、部署制品、提供程序恢复点及兼容的客户端构建版本，直至新检查点完成稳定性观察期。详情请参阅[升级部署与回滚](deployment-and-rollback.md)。

<a id="checklist"></a>

## 检查清单

- [ ] 更新到最新 Orleans 7.2 补丁版本并解决警告。
- [ ] 备份持久化状态，并盘点提供程序架构及序列化器契约。
- [ ] 单独将目标框架调整为 .NET 8。
- [ ] 升级至 Orleans 8.2，并修正选项及定时器迁移问题。
- [ ] 升级至 Orleans 9.2，并验证放置、取消、目录缓存及状态语义。
- [ ] 完成 Orleans 9 至 10 升级检查清单。
- [ ] 在每个检查点保持软件包版本一致。
- [ ] 在每个检查点测试旧状态读取、新状态写入、提醒器及流。
- [ ] 为每次主版本过渡演练并行集群部署与回滚。
