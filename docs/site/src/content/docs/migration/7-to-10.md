# 升级 Orleans 7.x 到 10.x

<a id="starting-and-target-assumptions"></a>

## 起始假设和目标假设

本指南假定:

- 应用程序首次更新到最新的 Orleans 7.2补丁。
- 应用程序可从 .NET 7至 .NET 8 之前通过 Orleans 8.
- 每一个主要转换检查站都可以独立部署和验证。
- 应用程序已经使用了 Orleans 7套软件、主机、身份和序列模型。

所支持的检查站顺序是:

1. 申请当前运行时间的最新 Orleans 7.2。
1. 最近 Orleans 8.2 on .NET 8.
1. 最近 Orleans 9.9.2至 .NET 8.
1. 现 Orleans 10x对A .NET 选定软件包所针对的版本。 Orleans 10.4和早先的一揽子目标 .NET 8和8 .NET 10;后期一揽子目标 .NET 和10和 .NET 11.

不要将 .NET 重新目标、 Orleans 软件包更新、供应商迁移和在一次生产部署中应用合同变更合并。

<a id="prepare-the-orleans-7-application"></a>

## 准备 Orleans 7号申请

移动到 Orleans 8:

- 将所有 `Microsoft.Orleans.*` 软件包对齐到同一最新的7.2 补丁。
- 删除过时的 API 并解析分析警告 。
- 确认 silos 使用 `Microsoft.Orleans.Server`,客户使用 `Microsoft.Orleans.Client`,共享合同项目使用 `Microsoft.Orleans.Sdk`。
- 确认主机使用 .NET 通用主机,且有 <xref:Microsoft.Extensions.Hosting.OrleansSiloGenericHostExtensions.UseOrleans*> 或 <xref:Microsoft.Extensions.Hosting.OrleansClientGenericHostExtensions.UseOrleansClient*>。
- 清单序列器成员身份、别名、供应商姓名、流分块计数和数据库图案。
- 捕捉代表坚持状态和测试的回收点。

呼叫过滤器应该已经使用 <xref:Orleans.Hosting.GrainCallFilterSiloBuilderExtensions.AddIncomingGrainCallFilter*> 或 <xref:Orleans.Hosting.GrainCallFilterSiloBuilderExtensions.AddOutgoingGrainCallFilter*> 在 Orleans 构建器上注册。旧的 <xref:Orleans.Hosting.GrainCallFilterServiceCollectionExtensions.AddGrainCallFilter*> API 已经从 Orleans 7 之前以来一直没有支持, 而不是 Orleans 10 更改 。

<a id="move-to-orleans-92"></a>

## 移动到 Orleans 9.2

完成 Orleans 9.9.2 检查站,说明如下: [升级 Orleans 8.x 到 10.x](8-to-10.md):

- 决定是接受 <xref:Orleans.Runtime.ResourceOptimizedPlacement>、新的违约,还是登记 <xref:Orleans.Runtime.RandomPlacement>。
- 删除适应性 grain- 指令缓存配置。
- 测试对齐的 <xref:Orleans.IGrainState`1> 读和清语义。
- 只有在运行时间检查站稳定之后才采用本地 <xref:System.Threading.CancellationToken> grain 方法参数。

<a id="move-to-orleans-10"></a>

## 移动到 Orleans 10

完成完成 [升级 Orleans 9. x 到 10.x](9-to-10.md). The Orleans 10项具体变化集中在:

- 过期 <xref:Orleans.Concurrency.UnorderedAttribute> 和 <xref:Orleans.OrleansConstructorAttribute> 说明。
- <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 默认值改为 `false`。
- SQL 服务器 ADO.NET 供应商正在移动到 `Microsoft.Data.SqlClient`。
- 取消支助扩大到观察员和系统目标。

通用主机模型、建筑商呼叫过滤器登记和耐版序列化模式仍在使用。

<a id="serialization-state-and-providers"></a>

## 分级、状态和提供者

Orleans 7 引入了后来释放后使用的识别和序列器模型,因此7-10升级不需要按要求转换身份 Orleans 3.

保留申请合同:

- 不再重新编号或再使用 <xref:Orleans.IdAttribute> 值。
- 保持类型或组装移动的 <xref:Orleans.AliasAttribute> 值稳定。
- 不要重订记录主构参数的订单
- 每次运行期升级期间,保存序列器和供应商名称稳定。
- 每个检查站都备有测试提醒、溪流订阅、排队有效载荷和代表性 grain 状态。
- 应用 ADO.NET 迁移脚本,在推进之前对每个提供者进行排序和验证。

<a id="deployment-and-rollback"></a>

## 部署和回缩

记录好的混合版本担保涵盖一个主要家庭内部的补丁和微小差异,而不是一组中的 Orleans 7、8、9和10。在每次重大过渡中使用平行集群,除非确切对应方通过了自己的混合版本测试套件。

保留上一个集群、部署文物、供应商回收点和兼容客户建设,直到新的检查站完成浸泡期。详情见 [升级部署和回调](deployment-and-rollback.md)。

<a id="checklist"></a>

## 核对列表

- [ ] 更新至最近的 Orleans 7.2补丁和解析警告。
- [ ] 支持耐久状态和库存供应商的计划书和序列器合同。
- [ ] 独立地重新瞄准 .NET 8。
- [ ] 升级至 Orleans 8.2,并固定选项和定时器迁移。
- [ ] 升级至 Orleans 9.2,并验证放置、取消、目录缓存和状态语义。
- [ ] 填写 Orleans 9-10核对表。
- [ ] 在每个检查站保持软件包版本对齐。
- [ ] 测试旧州读物,新州写作,提醒,在每个检查站的流。
- [ ] 在每个重大过渡阶段都进行平行分组部署和倒退。
