# 升级 Orleans 9. x 到 10.x

<a id="starting-and-target-assumptions"></a>

## 起始假设和目标假设

本指南假定:

- 应用程序运行于最新的 Orleans 9.x 补丁, 最好使用 Orleans 9.2.1。
- 应用程序及其依赖关系支持 a .NET 选定对象对象的版本 Orleans 软件包。
- 解决方案中的所有 Orleans 软件包将移到当前 Orleans 10.x 的补丁。
- 所部署的 Orleans 9.x 版本的供应方计划为当前。

Orleans 10.4和早先的一揽子目标 .NET 8和8 .NET 10. 后来 Orleans 软件包目标 .NET 和10和 .NET 11. 以单独、经验证的改动重新瞄准申请: Orleans 当选定软件包支持当前框架时或当 Orleans 之前的 9. 2 Orleans 当它们不更新时, 升级时会保持框架在 Orleans 升级可减少变量的数量。

<a id="change-summary"></a>

## 更改摘要

| 面积 | Orleans 10影响 | 要求采取的行动 |
|------|-------------------|-----------------|
| 源代码分析器 | <xref:Orleans.Concurrency.UnorderedAttribute> 和 <xref:Orleans.OrleansConstructorAttribute> 已过时 | 删除 <xref:Orleans.Concurrency.UnorderedAttribute>。仅在需要选择 DI 构造器时替换 <xref:Orleans.OrleansConstructorAttribute> 。 |
| 行为行为 | <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 现在默认为 `false` | 如果应用程序取决于超时后发送的取消, 请明确设置此选项 。 |
| ADO.NET 提供者 | SQL 服务器现在使用 `Microsoft.Data.SqlClient` 及其默认的变量名称 | 替换 `System.Data.SqlClient`,更新变量,测试每个 ADO.NET 提供者。 |
| 逐步化和状态 | Orleans 10不需要有线格式或 grain-- -- 从 Orleans 9改写国家 | 保存序列器识别码、别名、供应商序列器设置和存储类型兼容性。 |
| 东道主 | 通用主机主机 <xref:Microsoft.Extensions.Hosting.OrleansSiloGenericHostExtensions.UseOrleans*> 和 <xref:Microsoft.Extensions.Hosting.OrleansClientGenericHostExtensions.UseOrleansClient*> 模式保持目前状态 | 已经使用这些 API 的 Orleans 9 应用程序不需要重写主机。 |
| 安置职位安排 | Orleans 9.2 已经将默认值修改为 <xref:Orleans.Runtime.ResourceOptimizedPlacement> | 保留该数据,或如果需要确定性连续性,则在升级前明确登记 <xref:Orleans.Runtime.RandomPlacement> 。 |
| 注销 | Orleans 10 加增加对观察员和系统目标的取消支持 | 最多保留一个 <xref:System.Threading.CancellationToken> 参数,每 grain 方法和测试超时/取消赛跑。 |
| 计时器 | 没有新的 Orleans 10个计时器断开 | 继续使用 <xref:Orleans.GrainBaseExtensions.RegisterGrainTimer*>; <xref:Orleans.Grain.RegisterTimer*> 在 Orleans 8.2中已经过期。 |
| 调用过滤器 | 没有新建 Orleans 10 过滤器登记模式 | 继续在 <xref:Orleans.Hosting.ISiloBuilder> 或 <xref:Orleans.Hosting.IClientBuilder>上登记进出过滤器。 |
| 部署部署 | 交叉混合组群没有纳入文件文件的兼容性保障 | 使用平行 Orleans 10 组,除非您有确切的混合版地形学资格。 |

<a id="update-packages-centrally"></a>

## 集中更新软件包

保持软件包版本对齐。 例如, NuGet 中央软件包管理 :

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
    <OrleansVersion>10.2.2</OrleansVersion>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Microsoft.Orleans.Client" Version="$(OrleansVersion)" />
    <PackageVersion Include="Microsoft.Orleans.Sdk" Version="$(OrleansVersion)" />
    <PackageVersion Include="Microsoft.Orleans.Server" Version="$(OrleansVersion)" />
  </ItemGroup>
</Project>
```

在进行迁移时使用当前稳定的 Orleans 10.x 补丁。将解决方案所使用的每个供应商软件包添加到同一个中央文件,使用相同的 Orleans 版本。

<a id="review-source-warnings"></a>

## 审评源警告

<a id="remove--"></a>

### 删除 <xref:Orleans.Concurrency.UnorderedAttribute> <a name="remove-unordered"></a>

<xref:Orleans.Concurrency.UnorderedAttribute> has no effect because Orleans doesn't guarantee message ordering based on this attribute. Remove it from grain interfaces.

<a id="replace--only-for-dependency-injection-"></a>

### 仅替换依赖性注射的 <xref:Orleans.OrleansConstructorAttribute> <a name="replace-orleansconstructor-only-for-dependency-injection"></a>

<xref:Orleans.OrleansConstructorAttribute> is no longer recognized by Orleans. If a serializable type needs a constructor selected for dependency injection, use <xref:Orleans.GeneratedActivatorConstructorAttribute> or <xref:Microsoft.Extensions.DependencyInjection.ActivatorUtilitiesConstructorAttribute>. These attributes don't select a constructor for deserializing data members.

切勿改变会员身份或建筑工的可见状态 作为清理的一部分

<a id="make-timeout-cancellation-explicit"></a>

## 明确取消超时

Orleans 10 默认 <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 到 `false`。因此,一个超时呼叫器停止等待,但 Orleans 不自动发送取消到目标 。

设定此选项用于客户端和发端调用电话的 silos 。 超时不能证明目标停止执行, 不管是否使用, 所以 grain 方法必须保持安全重试 。

<a id="update-sql-server-adonet-configuration"></a>

## 更新 SQL 服务器 ADO.NET 配置

Orleans 10 ADO.NET 组合、持久性、提醒和流流使用 `Microsoft.Data.SqlClient` 用于 SQL 服务器

1. 删除直接的 `System.Data.SqlClient` 套件引用 。
1. 通过您的中央套件政策添加 `Microsoft.Data.SqlClient` 。使用由您应用程序支持的当前版本; 不要复制先前迁移指南中的旧定点版本 。
1. 将供应商的变量从 `System.Data.SqlClient` 改为 `Microsoft.Data.SqlClient`。
1. 在目前部署的系统图版与目标 Orleans 版本之间应用任何提供商所需的迁移脚本。
1. 独立地将测试组群、 grain 存储、提醒和流体进行分类。

使用仓库迁移目录 [组合](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Clustering.AdoNet/Migrations)、 [持久性](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Persistence.AdoNet/Migrations)和 [催复提醒](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Reminders.AdoNet/Migrations)。为数据库选择脚本,并按版本顺序应用脚本。

客户- 图书馆开关本身并不改变您的 grain- state 有效载荷格式。 它可以更改连接默认值和认证行为, 所以验证连接加密、 证书、 认证、 重试策略以及交易在运行中的行为 。

<a id="preserve-serialization-and-state-compatibility"></a>

## 保存序列化和州兼容性

没有任何 Orleans 9-10 迁移步骤要求重新编号 <xref:Orleans.IdAttribute> 值或重写状态。

- 不要重复使用或重新编号 <xref:Orleans.IdAttribute> 值。
- 当类型或组件移动时, 保持 <xref:Orleans.AliasAttribute> 值稳定。
- 不要重新订购记录作为隐性序列器ID使用的主要构件参数。
- 保持配置 grain- 在运行时间升级期间存储序列器不变。
- 读取代表旧状态,用 Orleans 10写,并核实回滚结构在允许制作之前仍然可以读到它。
- 应用 ADO.NET schema脚本,在应用任何不可逆脚本之前,先进行修改和校验回滚兼容性。

容忍规则版本见 [Orleans 序号](../host/configuration-guide/serialization.md)。

<a id="deploy-and-retain-rollback"></a>

## 部署和保留回滚

跟随 [升级部署和回调](deployment-and-rollback.md)。默认使用单独的 Orleans 10 组。保持 Orleans 9组及其最后一个兼容状态恢复点,直到:

- Orleans 10个客户和 silos 已经通过烟雾和装载测试。
- Orleans 10所写的数据经滚动构建证明可以读取。
- 没有排队或流行有效载荷包含 Orleans 9 无法使用的型号形状。
- 计量显示稳定的激活定位、调用延迟、取消、提醒和存储行为。

<a id="checklist"></a>

## 核对列表

- [ ] 更新到最新的 Orleans 9.x 补丁并删除构建警告 。
- [ ] 将每个 `Microsoft.Orleans.*` 软件包对齐到一个当前10.x的补丁。
- [ ] 将应用程序的 .NET 版本保留在第一次部署时使用,或将 .NET 10重新瞄准目标单独保留在 Orleans 9.2上。
- [ ] 删除 <xref:Orleans.Concurrency.UnorderedAttribute> 并替换有效的 <xref:Orleans.OrleansConstructorAttribute> 用途。
- [ ] 明确设置 <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 。
- [ ] 替换 `System.Data.SqlClient` 及其变量, 如果使用 SQL 服务器。
- [ ] 保存序列器识别码、别名和 grain-存储序列器设置。
- [ ] 确认预定的安置策略、时间间隔和电话过滤器登记。
- [ ] 验证供应商的阴谋和代表制度持续存在。
- [ ] 准备并排练平行集群部署和回击
