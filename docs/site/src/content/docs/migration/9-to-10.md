# 将 Orleans 9.x 升级到 10.x

<a id="starting-and-target-assumptions"></a>

## 起始版本与目标版本的前提条件

本指南假定：

- 应用程序运行在最新的 Orleans 9.x 补丁版本上，优先使用 Orleans 9.2.1。
- 应用程序及其依赖项支持所选 Orleans 程序包面向的某个 .NET 版本。
- 解决方案中的所有 Orleans 程序包将统一升级到同一个当前 Orleans 10.x 补丁版本。
- 提供程序的数据库架构已更新到所部署 Orleans 9.x 版本要求的状态。

Orleans 10.4 及更早的程序包面向 .NET 8 和 .NET 10。后续 Orleans 程序包面向 .NET 10 和 .NET 11。通过独立且经过验证的变更重新设定应用程序的目标框架：如果所选程序包支持当前框架，则在 Orleans 升级之后执行；否则先在 Orleans 9.2 上执行，再升级 Orleans。在升级 Orleans 时保持框架不变，可减少需要控制的变量。

<a id="change-summary"></a>

## 变更摘要

| 领域 | Orleans 10 的影响 | 必须执行的操作 |
|------|-------------------|-----------------|
| 源代码和分析器 | <xref:Orleans.Concurrency.UnorderedAttribute> 和 <xref:Orleans.OrleansConstructorAttribute> 已过时 | 移除 <xref:Orleans.Concurrency.UnorderedAttribute>。仅当需要通过 DI 选择构造函数时才替换 <xref:Orleans.OrleansConstructorAttribute>。 |
| 行为 | <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 现在默认为 `false` | 如果应用程序依赖于超时后发送取消请求的行为，则显式设置该选项。 |
| ADO.NET 提供程序 | SQL Server 现在默认使用 `Microsoft.Data.SqlClient` 及其固定提供程序名称 | 替换 `System.Data.SqlClient`，更新固定名称，并测试每个 ADO.NET 提供程序。 |
| 序列化和状态 | 从 Orleans 9 升级到 Orleans 10 无需重写传输格式或 Grain 状态 | 保持序列化器 ID、别名、提供程序序列化器设置和已存储类型的兼容性。 |
| 托管 | 通用主机的 <xref:Microsoft.Extensions.Hosting.OrleansSiloGenericHostExtensions.UseOrleans*> 和 <xref:Microsoft.Extensions.Hosting.OrleansClientGenericHostExtensions.UseOrleansClient*> 模型仍然适用 | 已使用这些 API 的 Orleans 9 应用程序无需重写托管代码。 |
| 放置 | Orleans 9.2 已将默认策略改为 <xref:Orleans.Runtime.ResourceOptimizedPlacement> | 保留该策略；如果必须确保放置行为连续一致，则在升级前显式注册 <xref:Orleans.Runtime.RandomPlacement>。 |
| 取消 | Orleans 10 新增了观察者和系统目标的取消支持 | 每个 Grain 方法最多保留一个 <xref:System.Threading.CancellationToken> 参数，并测试超时与取消的竞态条件。 |
| 定时器 | Orleans 10 没有新的定时器破坏性变更 | 继续使用 <xref:Orleans.GrainBaseExtensions.RegisterGrainTimer*>；<xref:Orleans.Grain.RegisterTimer*> 在 Orleans 8.2 中就已过时。 |
| 调用筛选器 | Orleans 10 没有新的筛选器注册模型 | 继续在 <xref:Orleans.Hosting.ISiloBuilder> 或 <xref:Orleans.Hosting.IClientBuilder> 上注册传入和传出调用筛选器。 |
| 部署 | 文档中的兼容性保证不涵盖跨主版本的混合集群 | 除非实际使用的混合版本拓扑已经过验证，否则使用并行部署的 Orleans 10 集群。 |

<a id="update-packages-centrally"></a>

## 集中更新程序包

保持程序包版本一致。例如，使用 NuGet 集中程序包管理：

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
    <OrleansVersion>10.2.2</OrleansVersion>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Microsoft.Orleans.Client" Version="$(OrleansVersion)" />
    <PackageVersion Include="Microsoft.Orleans.Sdk" Version="$(OrleansVersion)" />
    <PackageVersion Include="Microsoft.Orleans.Server" Version="$(OrleansVersion)" />
  </ItemGroup>
</Project>
```

迁移时使用当前稳定的 Orleans 10.x 补丁版本。将解决方案使用的每个提供程序包添加到同一个集中管理文件中，统一使用相同的 Orleans 版本。

<a id="review-source-warnings"></a>

## 检查源代码警告

<a id="remove--"></a>

### 移除 <xref:Orleans.Concurrency.UnorderedAttribute> <a name="remove-unordered"></a>

<xref:Orleans.Concurrency.UnorderedAttribute> 不起作用，因为 Orleans 不会根据此特性保证消息顺序。从 Grain 接口中移除该特性。

<a id="replace--only-for-dependency-injection-"></a>

### 仅为依赖注入替换 <xref:Orleans.OrleansConstructorAttribute> <a name="replace-orleansconstructor-only-for-dependency-injection"></a>

Orleans 不再识别 <xref:Orleans.OrleansConstructorAttribute>。如果可序列化类型需要为依赖注入指定构造函数，请使用 <xref:Orleans.GeneratedActivatorConstructorAttribute> 或 <xref:Microsoft.Extensions.DependencyInjection.ActivatorUtilitiesConstructorAttribute>。这些特性不会为数据成员的反序列化选择构造函数。

在进行此项清理时，不要更改成员 ID 或构造函数可见的状态。

<a id="make-timeout-cancellation-explicit"></a>

## 显式指定超时取消行为

Orleans 10 将 <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout> 的默认值设为 `false`。因此，超时的调用方将停止等待，但 Orleans 不会自动向目标发送取消请求。

:::code language="csharp" source="snippets/Orleans10MigrationExamples.cs" id="timeout_cancellation":::

在发起调用的客户端和 Silo 上设置此选项。无论此选项如何设置，超时都不能证明目标已经停止执行，因此 Grain 方法必须仍然能够安全重试。

<a id="update-sql-server-adonet-configuration"></a>

## 更新 SQL Server ADO.NET 配置

Orleans 10 的 ADO.NET 集群、持久化、提醒器和流式传输功能针对 SQL Server 使用 `Microsoft.Data.SqlClient`。

1. 移除对 `System.Data.SqlClient` 程序包的直接引用。
1. 通过集中程序包管理策略添加 `Microsoft.Data.SqlClient`。使用应用程序当前支持的版本；不要照搬早期迁移指南中固定的旧版本。
1. 将提供程序的固定名称从 `System.Data.SqlClient` 改为 `Microsoft.Data.SqlClient`。
1. 应用当前部署的数据库架构版本与目标 Orleans 版本之间所需的所有提供程序迁移脚本。
1. 分别测试集群、Grain 存储、提醒器和流式传输。

使用仓库中[集群](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Clustering.AdoNet/Migrations)、[持久化](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Persistence.AdoNet/Migrations)和[提醒器](https://github.com/dotnet/orleans/tree/main/src/AdoNet/Orleans.Reminders.AdoNet/Migrations)的迁移目录。为数据库选择适用的脚本，并按版本顺序应用。

客户端库的切换本身不会改变 Grain 状态的有效载荷格式。但它可能改变连接默认值和身份验证行为，因此请在预生产环境中验证连接加密、证书、身份验证、重试策略及事务行为。

<a id="preserve-serialization-and-state-compatibility"></a>

## 保持序列化和状态兼容性

Orleans 9 到 10 的迁移步骤均无需重新编号 <xref:Orleans.IdAttribute> 值或重写状态。保持现有契约：

- 不要复用或重新编号 <xref:Orleans.IdAttribute> 值。
- 类型或程序集发生移动时，保持 <xref:Orleans.AliasAttribute> 值稳定。
- 不要重新排列用作隐式序列化器 ID 的 record 主构造函数参数。
- 在升级运行时期间保持配置的 Grain 存储序列化器不变。
- 读取有代表性的旧状态，用 Orleans 10 写入，再确认回滚版本仍然能够读取，然后才允许生产写入。
- 按顺序应用 ADO.NET 数据库架构脚本，在应用任何不可逆脚本之前验证回滚兼容性。

有关版本容错规则，请参阅 [Orleans 序列化](../host/configuration-guide/serialization.md)。

<a id="deploy-and-retain-rollback"></a>

## 部署并保留回滚能力

遵循[升级部署与回滚](deployment-and-rollback.md)。默认使用独立的 Orleans 10 集群。保留 Orleans 9 集群及其最后一个兼容的状态恢复点，直至满足以下条件：

- Orleans 10 客户端和 Silo 已通过冒烟测试及负载测试。
- 已证明回滚版本能够读取 Orleans 10 写入的提供程序数据。
- 队列中或流中的有效载荷均不包含 Orleans 9 无法使用的类型结构。
- 指标显示激活放置、调用延迟、取消、提醒器和存储行为均保持稳定。

<a id="checklist"></a>

## 检查清单

- [ ] 更新到最新 Orleans 9.x 补丁版本，并消除构建警告。
- [ ] 将所有 `Microsoft.Orleans.*` 程序包统一到同一个当前 10.x 补丁版本。
- [ ] 首次部署时保持应用程序的 .NET 版本不变，或在 Orleans 9.2 上独立验证将目标框架改为 .NET 10 的变更。
- [ ] 移除 <xref:Orleans.Concurrency.UnorderedAttribute>，并替换有效的 <xref:Orleans.OrleansConstructorAttribute> 用法。
- [ ] 显式设置 <xref:Orleans.Configuration.MessagingOptions.CancelRequestOnTimeout>。
- [ ] 如果使用 SQL Server，则替换 `System.Data.SqlClient` 及其固定提供程序名称。
- [ ] 保留序列化器 ID、别名和 Grain 存储序列化器设置。
- [ ] 确认预期的放置策略、定时器交错执行方式及调用筛选器注册方式。
- [ ] 验证提供程序数据库架构及具有代表性的持久化状态。
- [ ] 准备并演练并行集群部署与回滚。
