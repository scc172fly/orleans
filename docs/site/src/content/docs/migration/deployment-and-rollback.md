<a id="upgrade-deployment-and-rollback"></a>

# 升级部署与回滚

<a id="compatibility-boundary"></a>

## 兼容性边界

Orleans 7 及以后版本使用版本容错序列化器，Orleans Grain 版本管理支持兼容的应用程序契约版本。不过，文档所述混合 Orleans 版本的运行时保证仅限于一个主版本系列内，例如 Orleans 9.x 的补丁版本和次版本。

对于主版本升级，默认应使用并行集群或蓝绿集群。在确切的运行时版本、提供程序、应用程序契约及流量模式通过自己的验证套件之前，应将混合主版本滚动升级视为不受支持。

<a id="rolling-upgrade-prerequisites"></a>

## 滚动升级的先决条件

在进行任何滚动部署之前（包括经过内部验证的跨主版本部署）：

- 所有 Silo 必须使用相同的集群提供程序、集群标识、提供程序配置和网络协议配置。
- 新旧二进制文件必须共享兼容的 Grain 接口方法签名。发布期间添加方法，而非更改或删除现有方法。
- 序列化类型必须保留两个版本都能读取的成员 ID、别名及结构。
- 整个回滚窗口内，两个版本均须能够读取提供程序架构及已存储的有效载荷。
- 流提供程序、队列分区数、提醒器提供程序、Grain 目录及放置策略必须支持混合拓扑。
- 无状态工作者及流代理必须单独考虑，因为 Grain 版本选择无法隔离它们。
- 部署必须具有自动化健康准入检查、流量排空、状态备份和经过测试的中止过程。

更改应用程序契约时，请使用[部署新版本的 Grain](../grains/grain-versioning/deploying-new-versions-of-grains.md) 中所述的兼容性及选择器策略。这些策略并不能确立运行时主版本之间的兼容性。

<a id="recommended-parallel-cluster-sequence"></a>

## 建议的并行集群部署顺序

1. 使用验证旧状态读取时采用的相同应用程序契约修订版本，构建目标版本。
1. 创建新集群，使其成员资格与网关发现独立于生产集群。
1. 将其指向克隆的提供程序数据或预发布数据集，验证集群、存储、提醒器、流、定时器、筛选器、取消与放置。
1. 在没有写入流量的情况下启动生产部署，并完成冒烟测试。
1. 切换一小部分可观测的流量。
1. 仅在延迟、失败、激活实例、存储、提醒器、流及取消指标保持稳定后增加流量。
1. 在进行任何可能导致并发激活或冲突写入的共享状态切换之前，停止向旧集群写入。
1. 保留旧部署及恢复点，直至回滚窗口结束。

除非提供程序和应用程序专门针对该拓扑进行了设计，否则不要让两个独立集群使用相同的 Grain 存储或提醒器表。

<a id="rollback-prerequisites"></a>

## 回滚先决条件

只有满足以下全部条件，回滚才是安全的：

- 先前运行时能够读取目标运行时写入的所有有效载荷和提供程序数据行。
- 数据库更改向后兼容，或者具备经过测试的数据库恢复方案。
- 已排队的工作无需使用任何新的 Grain 接口方法、序列化类型、流有效载荷或提醒器状态。
- 先前的软件包集合、配置、机密和部署映像仍然可用。
- 能够排空流量，而不会使两个集群同时拥有相同的逻辑激活实例。

如果任何条件未满足，回滚意味着恢复完整的升级前恢复点，而不仅仅是重新部署旧的二进制文件。

<a id="rollback-sequence"></a>

## 回滚顺序

1. 停止向目标集群发送新流量及写入。
1. 排空或妥善处理正在进行的调用及排队消息。
1. 如果先前版本无法读取目标版本的写入，则恢复提供程序数据。
1. 在隔离环境中启动先前集群。
1. 验证成员资格、提醒器、流、代表性状态及客户端调用。
1. 逐步恢复流量，并保留目标集群诊断信息供调查使用。

<a id="deployment-checklist"></a>

## 部署检查清单

- [ ] 确定变更是否限制在一个 Orleans 主版本系列内。
- [ ] 验证双向 Grain 接口及序列化器兼容性。
- [ ] 验证双向提供程序架构及有效载荷兼容性。
- [ ] 在适用时备份集群、提醒器、流及 Grain 状态。
- [ ] 测试旧状态读取及回滚读取。
- [ ] 演练流量排空、切换及回滚。
- [ ] 防止两个独立集群同时拥有相同的逻辑工作。
- [ ] 定义客观的健康准入条件及回滚截止时间。
