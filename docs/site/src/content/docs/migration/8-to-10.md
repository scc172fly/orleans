# 将 Orleans 8.x 升级到 10.x

<a id="starting-and-target-assumptions"></a>

## 起始版本与目标版本的前提条件

本指南假定：

- 应用程序可以先迁移到 .NET 8 上的 Orleans 8.2。
- 在将程序包升级到 Orleans 10.x 前，可以在 Orleans 9.2 上验证升级结果。
- 在每个检查点都可以备份和测试提供程序的架构及持久状态。
- 在每个检查点，所有 Orleans 程序包均同步升级。

不要在生产环境中直接从 Orleans 8 的早期版本跳到 Orleans 10。依次在最新的 8.2 补丁版本、Orleans 9.2 和选定的 Orleans 10.x 补丁版本上构建并测试应用程序。

<a id="orleans-8x-changes-to-complete-first"></a>

## 优先完成 Orleans 8.x 的变更

从 Orleans 8.2 之前的版本开始升级的应用程序必须考虑以下变更：

| 领域 | 变更 | 操作 |
|------|--------|--------|
| 负载削减 | Orleans 8.1 中，<xref:Orleans.Configuration.LoadSheddingOptions.LoadSheddingLimit> 被替换为 <xref:Orleans.Configuration.LoadSheddingOptions.CpuThreshold> | 重命名该选项，并检查新增的 <xref:Orleans.Configuration.LoadSheddingOptions.MemoryThreshold>。 |
| 流式传输 | Orleans 8.2 中修正了 <xref:Orleans.Configuration.LeaseBasedQueueBalancerOptions.LeaseAquisitionPeriod> 和 <xref:Orleans.Configuration.LeaseBasedQueueBalancerOptions.DefaultMinLeaseAquisitionPeriod> 的拼写 | 使用 <xref:Orleans.Configuration.LeaseBasedQueueBalancerOptions.LeaseAcquisitionPeriod> 和 <xref:Orleans.Configuration.LeaseBasedQueueBalancerOptions.DefaultMinLeaseAcquisitionPeriod>。 |
| 定时器 | Orleans 8.2 中，<xref:Orleans.GrainBaseExtensions.RegisterGrainTimer*> 替代了已过时的 <xref:Orleans.Grain.RegisterTimer*> API | 迁移回调，并根据实际需求选择 <xref:Orleans.Runtime.GrainTimerCreationOptions.Interleave> 和 <xref:Orleans.Runtime.GrainTimerCreationOptions.KeepAlive>。 |
| 序列化 | Orleans 8.2 开始支持 MessagePack 集成 | 除非另行验证，否则不要在运行时升级期间更换当前使用的序列化器。 |

## 验证 Orleans 9.2 检查点

Orleans 9.2 引入了一些行为变更，迁移到 Orleans 10 之前必须了解这些变更。

<a id="native--parameters"></a>

Grain 接口方法可以直接使用 <xref:System.Threading.CancellationToken>。现有的 <xref:Orleans.GrainCancellationToken> 代码可以独立迁移；不要将此 API 转换与业务逻辑变更合并进行。

<a id="resource-optimized-placement-is-the-default"></a>

### 默认采用资源优化放置策略

Orleans 9.2 将默认放置策略从 <xref:Orleans.Runtime.RandomPlacement> 改为 <xref:Orleans.Runtime.ResourceOptimizedPlacement>。这可能改变激活实例的分布及局部性。接受并对新默认策略进行负载测试，或者显式注册 <xref:Orleans.Runtime.RandomPlacement>：

<a id="grain-directory-caching"></a>

### Grain 目录缓存

Orleans 9.2 移除了自适应 Grain 目录缓存的实现。<xref:Orleans.Configuration.GrainDirectoryOptions.CachingStrategyType> 的 `Adaptive` 值作为 LRU 的过时别名保留。移除显式的自适应缓存配置，并根据生产环境的实际测量结果调整 LRU 缓存大小和过期时间。

<a id="grain-storage-behavior"></a>

### Grain 存储行为

Orleans 9.2 统一了存储提供程序的行为，使 <xref:Orleans.IGrainState`1.State>、<xref:Orleans.IGrainState`1.RecordExists> 和 <xref:Orleans.IGrainState`1.ETag> 在读取及清除操作之后遵循一致的规则。对每个提供程序测试激活初始化及 <xref:Orleans.Core.IStorage.ClearStateAsync*> 行为，尤其注意根据状态对象是否为 null 来推断记录是否存在的代码。

<a id="apply-the-orleans-10-changes"></a>

## 应用 Orleans 10 的变更

Orleans 9.2 检查点稳定后，完成[将 Orleans 9.x 升级到 10.x](9-to-10.md)中的每个步骤，包括：

- 移除已过时的 <xref:Orleans.Concurrency.UnorderedAttribute> 以及仍在使用的有效 <xref:Orleans.OrleansConstructorAttribute> 用法。
- 显式设置超时取消行为。
- 将 SQL Server ADO.NET 提供程序迁移至 `Microsoft.Data.SqlClient`。
- 保持托管、调用筛选器、序列化器契约和提供程序架构稳定。

<a id="serialization-and-state-compatibility"></a>

## 序列化与状态兼容性

Orleans 8、9 和 10 都使用 Orleans 7 引入的版本容错序列化器，但应用程序的变更仍可能导致已存储的数据不兼容。

- 保持所有 <xref:Orleans.IdAttribute> 和 <xref:Orleans.AliasAttribute> 值不变。
- 不要重新排列 record 主构造函数的参数。
- 不要在升级运行时主版本时更换存储序列化器。
- 在每个检查点测试旧状态读取和回滚版本读取。
- 保持流的分区数量及提供程序名称不变。
- 按顺序应用提供程序架构迁移，并保留迁移前的恢复点。

<a id="deployment-and-rollback"></a>

## 部署与回滚

8 到 9 以及 9 到 10 的生产环境迁移应分别使用独立集群，除非每一组混合主版本都已经过明确验证。Grain 接口版本控制有助于应用程序的不同版本共存，但不会将文档中的运行时兼容性保证扩展到单个 Orleans 主版本系列以外。

在每个检查点遵循[升级部署与回滚](deployment-and-rollback.md)。在回滚版本尚未针对迁移后的状态及提供程序架构完成测试之前，不要允许新集群执行写入。

<a id="checklist"></a>

## 检查清单

- [ ] 将应用程序升级到 .NET 8 上的最新 Orleans 8.2 补丁版本。
- [ ] 替换已重命名的负载削减和租约均衡器选项。
- [ ] 将 <xref:Orleans.Grain.RegisterTimer*> 迁移至 <xref:Orleans.GrainBaseExtensions.RegisterGrainTimer*>，并选择定时器选项。
- [ ] 使用最新 Orleans 9.2 补丁版本构建并测试应用程序。
- [ ] 确定保留资源优化放置策略还是注册随机放置策略。
- [ ] 移除自适应 Grain 目录缓存配置。
- [ ] 测试原生取消令牌及提供程序状态语义。
- [ ] 完成 Orleans 9 到 10 的检查清单。
- [ ] 在每个检查点验证序列化、流、提醒器和提供程序架构。
- [ ] 针对每次主版本迁移演练部署与回滚。
