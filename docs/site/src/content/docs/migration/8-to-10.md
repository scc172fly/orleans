# 升级 Orleans 8.x 到 10.x

<a id="starting-and-target-assumptions"></a>

## 起始假设和目标假设

本指南假定:

- 应用程序可以首先移动到 Orleans 8.2 on .NET 8.
- 升级可在 Orleans 9.2 后包件移到 Orleans 10.x.
- 可在每个检查站备份和测试提供方的计划和持久性状态。
- 所有 Orleans 包在每一个检查站一起移动。

在生产过程中,不要直接跳过早期 Orleans 8 释放到 Orleans 10。在最新的8.2补丁上构建和测试应用程序,然后是 Orleans 9.2, 然后是选定的 Orleans 10.x补丁。

<a id="grain-directory-caching"></a>

### Grain 目录缓存

适应 grain- 指令缓存实施在 Orleans 9.2. 缩略语 <xref:Orleans.Configuration.GrainDirectoryOptions.CachingStrategyType> 价值值 `Adaptive` 取消明确的适应性缓存配置,并根据生产量测量调整 LRU缓存大小和过期。

<a id="grain-storage-behavior"></a>

### Grain 存储行为

Orleans 9.2 统一的储存供应商,使 <xref:Orleans.IGrainState`1.State>、 <xref:Orleans.IGrainState`1.RecordExists>和 <xref:Orleans.IGrainState`1.ETag> 在读完并清除后遵循一致规则。每个供应商都进行测试启动初始化和行为 <xref:Orleans.Core.IStorage.ClearStateAsync*> ,特别是从无效物体中推断记录存在的代码。

<a id="apply-the-orleans-10-changes"></a>

## 应用 Orleans 10 更改

之后 Orleans 9.9 检查站稳定,每一步进入 [升级 Orleans 9. x 到 10.x](9-to-10.md)包括:

- 删除过期 <xref:Orleans.Concurrency.UnorderedAttribute> 和有效 <xref:Orleans.OrleansConstructorAttribute> 用途。
- 明确设定超时取消行为
- 将 SQL 服务器 ADO.NET 供应商移动到 `Microsoft.Data.SqlClient`。
- 保持主机、电话过滤器、连环转换器合同和供应商的系统稳定。

<a id="serialization-and-state-compatibility"></a>

## 分级和州兼容性

Orleans 8、9和10使用 Orleans 7中引入的耐版本序列器,但应用修改仍然会使存储的数据不兼容。

- 保持所有 <xref:Orleans.IdAttribute> 和 <xref:Orleans.AliasAttribute> 值稳定。
- 不要重订记录主构参数的订单
- 不要改变存储序列器 同时改变运行时主机
- 测试老州读数和回退读数在每个检查站之后。
- 保存流分割点和提供者名称 。
- 应用提供商的系统迁移来安排和保持移民前恢复点。

<a id="deployment-and-rollback"></a>

## 部署和回缩

在8-9和9-10生产过渡中使用单独的组群,除非对每对混合多数配对有明确限定。 Grain 界面版本有助于应用程序版本共存, 但不会将文件记录的运行时间保证延展到 1 Orleans 家庭主要组成。

在每个检查站跟随 [升级部署和回调](deployment-and-rollback.md) 。 在对后推结构进行测试之前, 不要允许在新组别中写字, 以测试结果的州和供应商计划 。

- [ ] 填写 Orleans 9-10核对表。
- [ ] 在每个检查站验证序列、流、提醒和供应商计划。
