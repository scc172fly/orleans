<a id="orleans-for-systems-big-and-small"></a>

# 适用于不同规模系统的 Orleans

无需非常大规模的部署，也能从 Orleans 中获益。虚拟 Actor 模型解决状态和工作跨越进程边界时即会出现的问题：标识、放置、并发、消息传递、成员资格及恢复。

<a id="start-in-one-process"></a>

## 从单进程开始

Orleans 应用可以在同一进程中托管一个 Silo 及其调用方。这对开发有用，也可能适合小型部署。Grain 标识及基于执行轮次的执行方式仍能提供有用的结构及隔离。

单个进程不具备容错能力；本地主机或内存提供程序也不会仅因应用使用 Orleans 而变成生产基础设施。根据所需的持久性和可用性选择提供程序及部署拓扑。

<a id="scale-by-partitioning"></a>

## 通过分区实现扩展

Orleans 应用通常将领域实体分区到许多 Grain 键。随着集群扩展，Orleans 可以在可用 Silo 上放置激活实例并路由调用，而无需更改 Grain 引用。

只有工作负载能够利用新增容量时，增加 Silo 才能提高集群容量。单个热点 Grain、共享外部依赖或全局协调点仍会成为瓶颈。度量键分布，并在需要时设计显式分区。

<a id="the-same-distributed-concerns-remain"></a>

## 分布式系统的共同问题仍然存在

无论集群有两个还是多个 Silo，应用都必须考虑：

- 调用可能失败、超时或被重试。
- 进程故障期间的成员资格变化及正在进行的工作。
- 持久化状态、提供程序可用性及恢复。
- 序列化及契约兼容性。
- 容量、过载、可观测性、部署及回滚。

Orleans 针对这些问题提供一致的模型及运行时服务，但不会消除这些问题，也不保证仅凭配置就能使应用扩展。

<a id="grow-without-encoding-locations"></a>

## 在不编码位置的情况下扩展

Grain 契约通过键而非服务器标识实体。因此，单进程应用和多 Silo 部署可以使用相同的领域接口。迁移到集群主要涉及托管、提供程序、安全及运维配置的变化。

这种与位置无关的模型在较小规模下同样有用，并会随着需求增长继续发挥作用。从满足当前要求的最简单拓扑开始，保留具有代表性的负载测试，并根据实际观察到的瓶颈进行扩展。
