<a id="failure-handling"></a>

# 处理失败

每一个 grain 电话都可能因调用者、目标 silo、网络、运行时间或依赖性失败而失败。超时或连接失败告诉调用者没有成功响应,无法证明 grain 方法没有运行。

<a id="treat-failed-calls-as-unknown-outcomes"></a>

## 将失败电话作为未知结果处理

考虑此顺序 :

1. grain 承诺提供或援引对外服务。
1. 响应因目标 silo 或网络失败而丢失。
1. 打电话者观察了暂停和重试。

原操作可能已经完成。 重试它为新操作可以重复电费、 保留、 信件或状态过渡 。 Orleans 可以重新启动 grain 并改序后再拨, 但无法推断先前呼叫的营业结果 。

分类操作 :

- **仅读**:当读作变换时通常可以安全重试,这是可以接受的。
- **自然无主**:重复相同的预期状态转让具有同样的效力。
- **复制**:操作带有稳定的ID,并存储结果进行重放。
- **非无行为能力者**:重复产生另一种效果,没有企业对账协议不得自动重新审理。

<a id="design-idempotent-operations"></a>

## 设计能干者操作

描述想要的状态或包括原调用者生成的操作代号的优先命令。 grain 可以:

1. 检查操作身份是否已经处理完毕
1. 如果是的话, 返回存储的结果 。
1. 应用国家过渡,记录操作编号,并原子结果在 grain 状态。
1. 坚持下去,然后承认成功。

仅在知道最大重试和重放窗口时, 才会按时间或计数来检查重复历史。 如果外部系统支持临时关键键, 则通过每次重试都传递相同的操作编号 。

状态 grain 的拖动不会产生与该状态独立的外部副作用原子。 当一个业务运作横跨商店时, 请使用发箱、 信箱、 程序管理器、 交易提供者或对账流程 。

<a id="bound-retries"></a>

## 油轨重转

仅在下列情况下重试:

- 失败是短暂的
- 操作可安全重复 。
- 电话的终端到终端截止时间还剩。
- 重算预算和货币限额允许再次尝试。

使用小尝试限制、指数回转和急躁。 荣誉取消和最后期限。 避免在每一层重试; 倍增重写可以使集及其依赖性超载 。

不要重试验证错误、授权失败、不兼容的有效载荷或确定性应用例外。 对于持续依赖性失灵,用断路器停止回转并返回明显退化或不可用的结果 。

<a id="coordinate-multi-step-work"></a>

## 协调多步骤工作

跨越 grains 调用和外部服务并非自动地一次性交易。 碰撞的协调员可以留下一些步骤,另一些步骤则不完整。

选择明确的一致模式:

- 选定储存提供者和工作量支持这些提供者的Orleans 交易。
- 进程经理或有持久进展和补偿行动的老生常谈。
- 发送信箱/信箱协议,用于可靠的信息发布和消费。
- 定期核对权威商业记录。

补偿是商业业务,而不是记忆回退,它也可能失败,必须无能。

<a id="preserve-evidence"></a>

## 保全证据

记录并跟踪稳定的操作编号、 尝试号、 截止时间、 grain 类型和结果类别。 不要使用 grain 键、 租户识别符号或有效载荷内装物作为未限制的度量尺寸 。

当结果仍未知时, 出现这种情况而不是报告成功或肯定失败。 让操作员或用户有一个状态调查与和解路径 。

<a id="test-failure-behavior"></a>

## 测试失败行为

国家持久性、 反应失败、 交付重复、 silo 终止、 供应商超时和在重新试镜窗口后恢复等测试失败。 校验商业变量,而不仅仅是检查重试最终返回是否成功。
