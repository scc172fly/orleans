# 生产集群运维

生产运维的目标是使 Orleans 集群保持在经过测试的容量、兼容性和恢复边界之内。利用本指南明确责任归属、控制变更、执行例行维护，并为每个环境编制运维操作手册。

<a id="understand-the-operating-boundaries"></a>

## 了解运维边界

各层分别提供不同的保证：

- 托管平台负责启动、监督、探测、扩缩容及终止 Silo 和客户端进程。
- 集群成员资格提供程序记录共享同一服务 ID 和集群 ID 的进程的集群成员资格及网关信息。
- Orleans 检测成员资格变更，将激活实例放置到可用的 Silo 上，并在 Silo 发生故障或退出后为后续调用进行路由。
- 持久化提供程序按照各自的一致性和可用性保证保存应用程序状态、提醒器、流状态及其他应用程序数据。
- 应用程序负责定义请求幂等性、授权、依赖项降级时的行为、数据兼容性和恢复目标。

为托管平台、网络、集群成员资格提供程序、Grain 存储、提醒器、流、机密、遥测及应用程序数据分别记录负责人和问题升级路径。提供程序的服务级别目标与配额也是 Orleans 服务运维边界的一部分。

<a id="maintain-an-environment-record"></a>

## 维护环境记录

为每个环境维护一份纳入版本控制的记录，其中包含：

- 服务 ID、集群 ID、区域、故障域以及提供程序命名空间。
- 部署制品摘要、Orleans 包版本、应用程序版本及配置修订版本。
- Silo 和客户端的资源请求量、资源限制、副本数下限、额外容量及扩缩容阈值。
- 已通告的 Silo 和网关终结点、监听终结点、DNS、防火墙和网络策略要求。
- 集群成员资格、存储、提醒器、流及 Grain 目录提供程序，以及它们的可用性级别和配额。
- 凭据及证书的来源、负责人、轮换流程及到期告警。
- 仪表板、告警规则、恢复目标、备份策略及经过测试的运维操作手册链接。

在部署时导出已移除机密的生效配置，并将其附到部署记录中，以便运维人员比较预期值与各进程实际使用的值。在日志和部署元数据中记录配置修订版本、应用程序版本、集群 ID、服务 ID 和 Silo 名称。

<a id="control-configuration-changes"></a>

## 控制配置变更

将配置视为受版本控制的部署输入。在测试环境和生产环境中依次推广同一份经过审查的制品，同时通过托管平台提供各环境专用的标识、终结点、凭据和容量配置值。

.NET 主机在启动 Orleans 之前组装配置。Orleans 运行时服务及提供程序在构造或启动时读取其选项，因此替换实例是应用 Orleans 配置修订版本的一致性边界。运行时重新加载配置是特定选项或提供程序所定义的契约；只有相应组件明确记录了重新加载后的行为时，才使用该功能。部署系统负责协调全部实例的配置修订版本，而每个 Orleans 进程则在启动时验证并应用自己的本地配置。有关绑定、优先级及提供程序配置，请参阅 [Orleans 配置指南](../host/configuration-guide/index.md)。

在发布前对每项变更进行分类：

| 变更 | 兼容性要求 | 发布方式 |
| --- | --- | --- |
| 遥测、告警或资源阈值 | 在新旧值共存期间，每个实例均可运行 | 滚动变更，同时监控饱和度和错误 |
| 终结点、集群成员资格提供程序、服务 ID 或集群 ID | 同一集群的所有参与者使用一致的标识和可达的通告终结点 | 协调迁移或建立新集群 |
| Grain 契约或序列化器 | 新旧调用方及实现之间能够交换兼容的有效载荷 | 先进行仅添加内容的变更，再滚动升级 |
| 持久化状态或提供程序的架构（schema） | 每个运行中的版本都能读取发布和回滚窗口期间写入的数据 | 扩展架构、部署、迁移，最后收缩架构 |
| 凭据或证书 | 提供程序及对等节点在重叠期内同时接受新旧凭据 | 添加新凭据、滚动更新、验证，再撤销旧凭据 |
| 容量或放置策略 | 剩余集群能够维持冗余并接纳迁移的激活实例 | 增量变更，并预留经过测量的稳定期 |

<a id="roll-out-a-configuration-revision"></a>

## 发布配置修订版本

1. 发布不可变的配置修订版本，并随附所需的应用程序镜像、包版本、提供程序架构修订版本及机密引用。
1. 在与生产环境形态相近的环境中验证配置及提供程序连通性。在仍可回滚的情况下，分别使用新旧修订版本验证由两个版本各自写入的数据。
1. 确认就绪 Silo 数量下限、额外容量、关闭时间预算、健康状态准入条件及回滚阈值。
1. 从应用程序流量中移除有限数量的实例，并执行[优雅关闭](upgrades.md#graceful-shutdown-and-scale-in)。
1. 使用新修订版本启动替代实例。等待启动及就绪过程完成、活动成员资格稳定，并确认[服务级别及依赖项指标](health-and-observability.md#telemetry)持续满足发布准入条件。
1. 将已脱敏的生效配置与预期修订版本进行比较，然后继续处理剩余故障域。
1. 保留旧镜像和旧配置修订版本，直到涉及写入、架构、凭据及排队工作项的所有回滚兼容条件所对应的有效期均已结束。

当发布超出回滚阈值，且旧版本仍能读取发布期间写入的每个有效载荷及提供程序记录时，恢复到旧镜像和旧配置修订版本。对于集群标识、通告终结点、提供程序命名空间的变更或不兼容的数据架构变更，则应使用协调迁移或隔离的蓝绿集群。有关兼容性边界及恢复顺序，请参阅[升级部署与回滚](../migration/deployment-and-rollback.md)。

<a id="perform-routine-maintenance"></a>

## 执行例行维护

根据实际测量的关闭、激活实例恢复、提供程序迁移和回滚耗时，确定维护窗口的长度。

1. 确认当前集群健康状况、就绪 Silo 数量、依赖项健康状况、备份状态及可用的额外容量。
1. 暂停无关部署及自动缩容。
1. 记录部署修订版本及生效配置的修订版本。
1. 从应用程序流量中移除一个 Silo 或故障域，并开始优雅关闭主机。
1. 等待成员资格稳定，并确认剩余 Silo 能够承担重新激活的负载，且不超过延迟、饱和度或错误阈值。
1. 应用主机、运行时、提供程序、凭据或基础设施变更。
1. 待实例完成启动并就绪后，将其重新投入服务。
1. 在经过测试的中断预算内重复上述步骤。
1. 记录结果、实际观测到的恢复时间，以及对运维操作手册所作的任何修正。

对于提供程序维护，必须维持其文档规定的法定人数、可用性及备份保证。在安排存储维护时，应为 Orleans 预留充足容量，以承受激活和状态加载延迟的增加。在安排集群成员资格提供程序维护时，应为提供程序预留充足容量，以处理成员资格心跳、网关发现和发布期间的成员频繁变动。

<a id="run-regular-operational-exercises"></a>

## 定期开展运维演练

演练生产恢复所依赖的行为：

- 在具有代表性的流量持续运行时替换一个 Silo。
- 模拟一个经过测试的故障域失效，并验证容量余量。
- 将持久化的应用程序数据还原到隔离的恢复环境中。
- 在新旧凭据及证书的重叠期内进行轮换。
- 在混合版本运行期间，将兼容版本向前升级并回滚。
- 模拟每个必需依赖项发生降级，并验证准入控制、超时、熔断及告警行为。
- 对调用方发生超时、结果未知的操作进行核对及协调处理。

记录恢复时间、用户影响、提供程序负载、激活速率及运维人员的决策。将实际观测到的限制反馈到[容量规划](capacity-planning.md)、[健康状态与告警](health-and-observability.md)和[生产就绪检查清单](production-readiness.md)中。

<a id="prepare-runbooks"></a>

## 编制运维操作手册

每条需要运维人员采取行动的告警都应链接到一份运维操作手册，其中包含：

1. 用户可见的症状及触发该操作手册的指标。
1. 受影响的集群、提供程序、部署和故障边界。
1. 安全的稳定化措施，以及停止发布的条件。
1. 命令或平台操作流程，以及所需权限和预期结果。
1. 在替换或重启实例前需要保留的证据。
1. 问题升级条件及各依赖项的负责人。
1. 恢复验证，包括成员资格稳定性、依赖项健康状况、延迟、错误及数据协调核对。

优先为发布失败、部分网络分区、集群成员资格提供程序中断、存储降级、过载、凭据过期、证书轮换、备份还原及区域级恢复编制运维操作手册。有关故障处理流程及证据检查清单，请参阅[部署故障排查](troubleshooting-deployments.md)。
