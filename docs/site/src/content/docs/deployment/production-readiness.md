<a id="production-readiness-checklist"></a>

# 生产就绪检查清单

为每个生产环境完成此检查清单。记录负责人、预期值及运维手册链接，不要依赖平台隐含的默认值。

<a id="identity-and-compatibility"></a>

## 标识与兼容性

- [ ] 每个 Silo 和客户端都使用预期的 Orleans 软件包版本。
- [ ] <xref:Orleans.Configuration.ClusterOptions.ServiceId> 在应用程序整个生命周期内保持稳定，且不被无关应用程序复用。
- [ ] <xref:Orleans.Configuration.ClusterOptions.ClusterId> 标识当前部署环境。生产、预发布和蓝绿集群使用不同的值，除非有意加入同一个集群。
- [ ] Grain 接口、序列化器和持久化状态的变更与所选[升级策略](upgrades.md)兼容。

<a id="networking-and-discovery"></a>

## 网络与发现

- [ ] 每个 Silo 公布的地址和 Silo 端口都能被其他所有 Silo 访问。
- [ ] 每个外部 Orleans 客户端都能访问公布的网关地址及端口。
- [ ] 侦听端点绑定到进程内可用的网络接口；公布端点描述其他节点访问该进程的方式。
- [ ] 网络策略、防火墙、服务网格和网络地址转换能够维持长时间的双向 TCP 连接。
- [ ] Silo 与客户端使用相同的生产[集群提供程序和集群标识](networking.md#choose-a-clustering-provider)。
- [ ] 集群提供程序具有高可用性，已经过容量测试，并在各环境之间适当隔离。

<a id="state-and-dependencies"></a>

## 状态与依赖项

- [ ] 每个 Grain 存储、提醒器、流和集群提供程序均已针对生产环境显式配置。
- [ ] 在激活实例或集群丢失后仍需保留的数据使用持久化 Grain 存储。仅可丢弃的数据使用内存存储。
- [ ] 在可用时，依赖项使用工作负载标识或其他短期凭据机制。机密信息不嵌入镜像、源码或部署清单。
- [ ] 超时、并发限制、熔断器和[有界重试策略](handling-failures.md)可防止依赖项故障演变为重试风暴。
- [ ] 已记录依赖项降级或不可用时的行为：默认拒绝、拒绝工作请求、提供过时数据，或缓冲有限数量的工作。

<a id="lifecycle-and-health"></a>

## 生命周期与健康检查

- [ ] 启动期间保持未就绪状态，直到 Silo 加入集群且所需依赖项可用。
- [ ] 在缩容或关闭开始之前，撤销就绪状态。
- [ ] 存活检查仅用于检测本地无法继续运行的进程，不应仅因远程依赖项不可用而重启进程。
- [ ] 平台的终止宽限期长于主机关闭超时时间和实测的 Silo 优雅关闭所需时间。
- [ ] 滚动部署设置能保留足够的就绪 Silo 以维持容量。

<a id="security-and-access"></a>

## 安全与访问

- [ ] 已记录 [Orleans 信任边界](../security/index.md)和由应用程序负责的安全控制措施。
- [ ] 只有受信任的工作负载能够访问 Silo 及网关端口。
- [ ] 当网络本身并非可信且隔离的边界时，应配置 Orleans 传输安全。参阅 [Orleans 传输层安全](../host/transport-layer-security.md)。
- [ ] Grain 调用执行[应用程序身份验证与授权](../security/authentication-authorization.md)，并由经过验证的凭据确定通过请求上下文传递的身份。
- [ ] 序列化器的类型名称解析遵守[最小权限类型策略](../security/serialization.md)。
- [ ] 管理端点、健康详情、指标及日志均不暴露机密信息或租户数据。
- [ ] 提供程序标识具有访问成员资格数据、状态、提醒器及流所需的最小权限。
- [ ] 证书及凭据具有轮换及到期告警。

<a id="observability-and-operations"></a>

## 可观测性与运维

- [ ] 日志、Orleans 指标、.NET 运行时指标及跟踪均集中导出。参阅 [Orleans 可观测性](../host/monitoring/index.md)。
- [ ] 仪表板展示就绪 Silo 数量、成员资格变更、请求延迟及失败、被拒绝或丢弃的消息、激活实例数量、CPU、内存及依赖项健康状态。
- [ ] 告警依据用户影响及持续症状触发，而不是依据单个暂时性的成员资格事件。
- [ ] 运维人员能够跨日志及遥测关联部署版本、Silo 名称、集群 ID、服务 ID 和主机实例。
- [ ] 已按照[生产运维指南](production-operations.md)为发布失败、部分网络分区、提供程序中断、过载、数据还原及凭据到期指定负责人并编写运维手册。

<a id="capacity-and-recovery"></a>

## 容量与恢复

- [ ] 负载测试包括预期流量、突发流量、热点 Grain 键、Silo 丢失及依赖项变慢等情况。
- [ ] 伸缩策略依据实测的饱和程度，并留有至少一个故障域丢失时所需的余量。
- [ ] 持久化应用程序数据已备份，并通过还原测试。
- [ ] 恢复目标区分成员资格数据、Grain 状态、提醒器数据、流状态及应用程序数据库。
- [ ] 灾难恢复演练已证明所记录的[还原流程](disaster-recovery.md)可行。

上线前，在持续施加类似生产环境负载的情况下执行受控重启，并逐个 Silo 进行缩容。任何正确性保证都不应依赖优雅关闭成功，因为进程始终可能突然故障。
