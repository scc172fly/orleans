<a id="health-and-observability"></a>

# 健康检查与可观测性

健康检查终结点由应用程序负责实现。Orleans 集群成员资格机制可以检测发生故障的 Silo，但不能替代编排器探针或依赖项健康检查。

<a id="separate-the-health-signals"></a>

## 区分不同的健康信号

| 信号 | 要回答的问题 | 失败时的操作 |
| --- | --- | --- |
| 启动（Startup） | 是否在允许的时间窗口内完成初始化？ | 推迟存活和就绪状态的评估；仅在超过启动期限后重启 |
| 就绪（Readiness） | 此实例是否应该接收新的应用程序流量？ | 停止向该实例分发流量，但不重启它 |
| 存活（Liveness） | 此进程在本地是否仍能继续推进工作？ | 重启进程 |
| 依赖项健康状态 | 哪个必需或可选依赖项的服务能力已下降？ | 根据应用程序策略降级、拒绝请求或发出告警 |

不要让存活检查依赖集群提供程序、Grain 存储、远程 Silo 或其他网络服务。共享依赖项发生故障时，这种设计会导致所有实例同时重启，增加负载并丢失有价值的诊断信息。

<a id="startup"></a>

## 启动

在满足以下条件前，启动状态应保持为未完成：

- 配置和凭据有效。
- 必需的侦听器已完成绑定。
- Silo 已加入预期的集群。
- 安全接收流量所需的依赖项已完成初始化。

平台的启动期限应长于实测的最长初始化时间，其中应包括成员资格清理和提供程序恢复所需的时间。启动失败时，应在平台重启进程之前记录失败的阶段、依赖项和异常。

<a id="readiness"></a>

## 就绪

出现下列情况时，就绪状态应变为 false：

- Silo 尚未完成启动。
- 已开始优雅关闭或缩容。
- 应用程序无法安全地接收新工作。
- 必需的依赖项不可用，且应用程序没有安全的降级模式。
- 本地资源饱和程度超过经过审慎选择的负载削减阈值。

如果应用程序能够按照文档约定提供降级响应，则不要将可选依赖项纳入整体就绪状态的判断。单独发布它们的状态，并在持续降级时发出告警。

从负载均衡器中移除 HTTP 终结点并不会阻止直接的 Orleans 流量。关闭期间，应将取消就绪状态与主机的优雅关闭相结合，并预留足够的时间让 Silo 退出集群成员资格。

<a id="liveness"></a>

## 存活

使用开销低的本地检查。可以验证健康检查终结点能否响应，以及本地进度信号是否在一个较为宽松的时间间隔内有所推进。避免调用 Grain 或执行远程 I/O。

允许垃圾回收、CPU 争用或诊断数据收集导致的短暂停顿。过于激进的存活检查阈值会使暂时性的过载演变为反复重启。

<a id="dependency-degradation"></a>

## 依赖项降级

部署前对依赖项进行分类：

- **正确性所必需的依赖项**：不可用时拒绝接收新工作。
- **持久性所必需的依赖项**：不要确认无法满足持久性要求的操作。
- **可选依赖项**：以可观测的降级模式继续运行。
- **异步依赖项**：仅在容量有明确上限且受到监控的情况下进行缓冲。

在每个远程调用边界设置超时和并发限制。使用熔断器停止对不健康依赖项的重复调用。仅当操作可以安全重复且调用方仍有可用时间时才重试。

<a id="telemetry"></a>

## 遥测

Orleans 使用 `Microsoft.Extensions.Logging`、`System.Diagnostics.Metrics` 和分布式跟踪。配置集中式导出器，参阅 [Orleans 可观测性](../host/monitoring/index.md) 以配置信号，并通过[监控 Orleans 指标](../host/monitoring/metrics.md) 了解运行时度量工具的含义。

至少应关联以下维度：

- 服务 ID、集群 ID、部署版本、Silo 名称和主机实例。
- Grain 类型和操作名称，但要确保维度的基数有界。
- 依赖项名称和结果，不将 Grain 键、机密或租户数据作为指标维度。

监控以下内容：

- 已就绪和活动的 Silo 数量、加入、离开及疑似故障的 Silo。
- Grain 调用速率、延迟、超时、拒绝、丢弃的消息及失败情况。
- 激活实例数量、激活失败、调度器延迟和长时间运行的执行轮次。
- 网关连接和负载削减。
- 进程 CPU、内存分配速率、垃圾回收、工作集、线程池和套接字数量。
- 提供程序延迟、限流、错误、容量、凭据到期情况及熔断器状态。

当用户持续受到影响、冗余度下降、资源饱和或错误预算耗尽时发出告警。在受控发布期间，单个 Silo 离开集群是一个需要关联分析的事件，不一定构成事故。
