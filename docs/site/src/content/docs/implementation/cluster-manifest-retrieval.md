# 集群清单获取

每个 Silo 发布一份不可变的 Grain 清单，描述其 Grain 类型、接口和属性。集群清单提供程序将这些清单汇总为用于类型解析和版本感知放置的元数据。

<a id="membership-and-publication"></a>

## 成员资格与发布

集群清单的主版本号对应成员资格版本，次版本号随清单到达而推进。当成员资格版本推进时，提供程序同步移除非活动 Silo，并在本地 Silo 处于活动状态时将其纳入清单。本地 Silo 启动期间也可以使用本地 Grain 元数据。

提供程序获取缺失的活动 Silo 清单，并发布成功获取的结果。获取失败时，在五秒后或收到更新的成员资格快照时重试。取消信号会传递到远程调用并结束本地等待。

<a id="content-addressed-retrieval"></a>

## 内容寻址获取

<xref:Orleans.Configuration.ClusterManifestOptions.EnableContentAddressedRetrieval> 默认为 `true`，启用基于哈希的获取及对等节点修复。将其设置为 `false`（位于 <xref:Orleans.Configuration.ClusterManifestOptions> 中），可直接请求每个缺失清单的活动 Silo 的清单。在启动 Silo 之前通过 Silo 构建器配置此选项。提供程序在构造时捕获该值；必须重启才能应用配置变更。

启用此选项后，提供程序向每个缺失清单的 Silo 请求其本地清单的内容哈希。如果本地哈希缓存存在匹配项，则直接提供清单。否则，提供程序按哈希请求清单，验证其内容并将其加入缓存。

哈希使用增量 SHA-256 算法，按固定的规范化遍历顺序计算：编码版本、已排序的 Grain 条目，然后是已排序的接口条目。每个区段和属性集合均以其数量开头。标识符以字节长度为前缀；属性键和值以 UTF-16 代码单元长度为前缀。长度 `-1` 表示 null 或默认标识符，而 `0` 表示空值。数量和长度为有符号 32 位大端序整数，UTF-16 代码单元按大端序写入。这种布局精确保留标识符的字节及字符串内容（包括无效的 UTF-16），使内容等价的清单具有相同哈希，而不受字典插入顺序影响。不可变清单实例的哈希使用弱引用键记忆化缓存，因此当其所有者释放清单时，清单可以被垃圾回收。

每次发布都会创建新的缓存，其中包含当前仍有效的清单和本地元数据。进行中的获取操作保留其原有缓存实例。过时的获取操作可以填充该实例，而较新的发布仍保留自己的缓存。提供程序先公开新清单版本，再公开新缓存。获取操作先捕获缓存，再检查版本，因此如果较旧的更新捕获了较新的缓存，它也会观察到其成员资格快照已被更新的快照取代。

<a id="peer-repair-and-bounded-waiting"></a>

## 对等节点修复和有界等待

当缺失多个活动 Silo 的清单时，启用了该功能的提供程序还会从轮换的有序成员列表中选择至多三个对等节点进行探测。直接获取与这些探测同时启动。

每次探测的哈希摘要请求和清单更新请求共享一秒的截止时间。缓存中的哈希可以直接满足缺失条目；否则，提供程序向对等节点请求完整更新，并根据摘要中的哈希验证每个候选清单。修复成功的条目会立即发布，包括部分修复。针对这些条目的直接请求从必需完成集合中移除，使剩余成功的获取操作可以独立推动清单更新。

当直接获取首先提供全部缺失的清单时，提供程序取消可选的对等节点获取尝试，并立即发布直接获取结果。因此，成功的直接获取路径无需等待缓慢的对等节点摘要请求就能完成。

提供程序最多准入三次并发的本地探测尝试。完成、超时和调用方取消都会立即释放相应尝试的槽位，允许后续重试继续进行。一秒的截止时间会取消请求令牌并结束本地等待；Orleans 通过正常的 RPC 路径向对等节点发送取消信号。直接获取与这些尝试并行进行。迟到的响应不会改变已完成尝试的结果，迟到的故障会被观察并记录到日志。重试在活动对等节点间轮换选择，重试节奏由五秒延迟或更新的成员资格快照控制。

<a id="compatibility-rollout-and-rollback"></a>

## 兼容性、滚动发布和回滚

Silo 按需响应哈希请求，包括已配置为直接获取的 Silo。使用默认内容寻址模式的提供程序会在清单可用时计算并复用内容哈希。

在滚动部署期间，启用该功能的 Silo 尝试基于哈希获取清单；当对等节点拒绝较新的方法或哈希请求失败时，回退到既有的直接 RPC。无效或不可用的哈希寻址消息体也会触发直接获取。独立发生的远程取消走这一兼容性路径；本地请求的取消则传播给调用方。对等节点修复失败时，由直接获取继续填补缺失条目。

已升级的 Silo 在启动时采用内容寻址获取，而现有 Silo 继续使用其已部署的实现。升级期间，不受支持的哈希请求可能产生短暂的异常日志及额外请求；成功的直接回退提供所需元数据。单个 Silo 清单 RPC 保留已配置的系统响应超时，而可选的对等节点摘要或更新尝试具有一秒的截止时间。

在加入集群和重启期间，观察清单获取及对等节点探测的诊断信息。调试日志区分哈希获取回退、对等节点超时、探测槽位已占用及迟到故障。警告日志标识失败的直接获取。若要选择直接获取，将选项设置为 `false` 并重启受影响的 Silo；这些 Silo 仍会按需响应启用了该功能的对等节点的哈希请求。

<a id="measuring-retrieval"></a>

## 衡量获取情况

`Microsoft.Orleans` Meter 公开[清单获取指标](../host/monitoring/metrics-catalog.md#cluster-manifests)。在等效的加入和重启场景中，将金丝雀部署与使用直接获取的 Silo 进行比较：

| 指标 | 含义 |
|---|---|
| `orleans-manifest-cache-lookups`，按 `result` 和 `source` 分组 | 命中比例反映已知内容满足直接哈希请求或对等节点摘要查找的频率。 |
| `orleans-manifest-fallbacks`，按 `reason` 分组 | 统计在发生错误、消息体缺失或内容不匹配后改为直接 RPC 的哈希获取操作。 |
| `orleans-manifest-peer-probes`，按 `status` 分组 | 显示已完成的本地尝试、超时、取消、错误和因准入限制而跳过的操作。取消也包括被成功的直接获取取代的可选探测。 |
| `orleans-manifest-peer-repairs` | 统计由已成功发布的对等节点修复补齐的缺失 Silo 条目。重复的摘要在每次发布中仅为每个已修复条目贡献一次计数。 |
| `orleans-manifest-retrieval-duration`，按 `mode` 和 `status` 分组 | 以毫秒为单位度量每次本地 Silo 清单获取，包括缓存查找、回退以及最终的取消或失败。 |

属性使用固定类别，因此在 Silo 重启前后时间序列基数保持稳定。直接模式记录获取耗时，哈希和对等节点计数器则反映内容寻址获取活动。结合这些指标、序列化消息大小及 Silo 的 CPU 和内存用量，评估该功能对服务清单大小和应用版本组合所带来的收益。

有关成员资格转换，请参阅[集群成员资格](cluster-management.md)；有关清单元数据如何驱动接口版本选择，请参阅[滚动部署中的版本偏差](rolling-version-skew.md)。
