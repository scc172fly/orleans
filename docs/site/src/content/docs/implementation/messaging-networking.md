<a id="transport-and-networking-internals"></a>

# 传输与网络内部机制

Orleans 将消息路由与传输管理分开。`MessageCenter` 决定消息应发送到何处；`ConnectionManager` 获取到目标 Silo 的可用连接；连接实现将消息分批并分帧为发送给消息传输层的请求。这种分离让路由能够修复激活实例地址，而传输层负责读、写和完成回调。

<a id="connection-lifecycle"></a>

## 连接生命周期

对每个远程 `SiloAddress`，`ConnectionManager` 维护一个 `ConnectionEntry`，其中包含活跃连接、待完成的连接尝试及上次失败时间。`GetConnection` 复用合适的活跃连接。活跃连接不足时，它为每个端点启动一个共享的待完成连接尝试，并发发送方等待该尝试。

连接建立受 `OpenConnectionTimeout` 限制。尝试失败时清除待完成任务、移除失效连接、记录失败，并在再次尝试之前应用配置的重试延迟。超时将传输尝试判定为失败；应用处理结果需要单独协调确认。

对等节点的协议前导信息通过验证且本地前导信息写入完成后，Silo 连接才可用于发送消息。此握手边界确保每个前导信息在传输层上先于分帧消息，包括对等节点在本地写入排队之前就发送了其前导信息的情况。TCP、Unix 域套接字、内存连接及 TLS 装饰连接共享此发布边界。TLS 身份验证在传输层处理 Orleans 前导信息及消息请求之前完成。

传出连接建立流程将与关闭关联的 `OpenConnectionTimeout` 令牌贯穿连接器创建、TLS 身份验证及协议初始化过程。侦听器绑定在分配或注册端点之前检查启动取消状态。传入侦听器将其关闭令牌贯穿接受连接及初始化过程。TLS 身份验证将建立阶段取消、底层传输关闭及 `HandshakeTimeout` 关联起来；最先发生的信号中断身份验证，并使已排队请求以该失败结果完成。协议初始化在发布就绪状态之前检查取消。初始化完成后，连接生命周期由传输关闭以及拥有它的管理器或侦听器控制。

连接建立被取消时，管理器和侦听器关闭其拥有的传输实例，以中断待完成的前导信息读写。已接纳的传输请求在释放其缓冲区之前完成，因此取消清理在释放连接之前排空这些操作。

源码：[`ConnectionManager`](https://github.com/dotnet/orleans/blob/main/src/Orleans.Core/Networking/ConnectionManager.cs)、[`Connection`](https://github.com/dotnet/orleans/blob/main/src/Orleans.Core/Networking/Connection.cs) 和 [`SiloConnection`](https://github.com/dotnet/orleans/blob/main/src/Orleans.Runtime/Networking/SiloConnection.cs)。

TCP 传输在传出及已接受的套接字上启用保活。默认情况下，操作系统在空闲 90 秒后发送第一次探测，之后每 30 秒探测一次，允许连续 10 次未得到响应的探测后终止连接。已接受的套接字使用其命名侦听器的当前选项，因此每个 Silo 或网关侦听器将其配置的保活策略应用于新连接。平台报告某个不受支持的保活选项时，传输层记录该选项并保留受支持的设置；继续调节其他受支持的选项。

<a id="message-path-and-framing"></a>

## 消息路径与分帧

当 `MessageCenter.SendMessage` 存在目标 Silo 时，复用现有连接或从 `ConnectionManager` 获取连接。本地目标直接使用接收处理流程。已知死亡的目标会导致请求及单向消息收到瞬态拒绝，过期消息在消耗传输资源之前被丢弃。

连接管道先进行协议前导信息交换，再交换已分帧的有效载荷。`MessageSerializer` 使用 Orleans 序列化编码消息标头及消息体。`MessageReadRequest` 在使用标头及消息体之前验证帧长度。消息体保持缓冲状态，直到反序列化、转发或释放操作将其释放。TLS 对消息传输层进行装饰，同时保留 Orleans 的分帧和消息协议。

连接通过无界队列接受传出消息。发送工作器将消息分批为写入请求；传输写入方遵守流量控制，并发发送方仍可继续向连接队列添加消息。因此，慢速连接可能持续累积排队消息，直到恢复或关闭。成功写入后请求完成，并释放其缓冲的消息体；Grain 返回的结果才确认应用请求完成。断开连接时从端点条目移除该连接，后续发送将建立替代连接。

<a id="failure-and-shutdown"></a>

## 故障与关闭

连接终止时，失败的写入请求及排队发送工作通过连接专用的 `RetryMessage` 实现重新路由其消息。该实现在重试上限内将消息返回 `MessageCenter` 进行路由，达到上限后拒绝请求并丢弃其他消息。仅部分写入的请求也可能在故障发生前到达目标，因此应用应依据自身投递和幂等性要求协调未知结果。

关闭首先阻止新应用流量，同时允许完成停止协议所需的响应及成员资格流量。`MessageCenter` 拒绝或丢弃被阻止的消息，停止接受客户端消息，然后关闭连接。到达正在停止的 Silo 的传入应用请求收到带定向缓存失效的瞬态拒绝，使发送方能够移除通往该 Silo 的路由。其他传入应用消息被丢弃，并释放其缓冲的消息体。

`ConnectionManager` 在取消待完成尝试及通知现有连接关闭之前，先关闭连接建立的准入。每个已准入的生产者仍归其所有者管理，直到发布连接或完成失败清理，包括其连接运行器。关闭随后关闭任何迟到的已发布连接，并通过中间件清理流程排空其余传出连接运行器。关闭取消源在这些操作完成之前保持有效；如果宿主停止过程被取消，仍会为正在进行收尾清理的操作保留该取消源。传入侦听器停止接受连接，并关闭所跟踪的连接，随后等待管理器的关闭信号并释放其传输侦听器。

关闭连接会停止发送工作的准入，并关闭消息传输层以解除待完成的 TLS 握手、前导信息交换及传输 I/O。连接运行器和发送工作器停止活动之后，释放传输层会释放整个装饰传输链。在排队的运行器启动之前已关闭的连接，会在协议初始化之前完成传输关闭。

<a id="design-trade-offs"></a>

## 设计权衡

- 按端点维护连接状态避免了全局协调，但意味着每个 Silo 必须观察并修复自身故障的通信路径。
- 复用连接可降低握手及分配成本，而多个连接能够改善吞吐量并避免队头阻塞。
- 丢弃过期消息可保护饱和的运行时，使其无需处理回调截止时间已过的工作。应用使用操作 ID 和持久化状态协调操作结果。

端到端语义参见[消息传递与投递语义](messaging-delivery-guarantees.md)。网络端点选择和防火墙要求参见[拓扑、网络与集群配置](../deployment/networking.md)。
